# Day13 시작 안내 - 누가 이 폴더를 쓰나요?
<!-- spec_ref: 주차나선 SOT §9 D13 + 한얼 260804 확정(오전=상세 라우트, 오후=규칙판, day13-starter 독립실행) -->

이 폴더는 **어제(Day12) 완료 상태가 미리 세팅된 공용 시작점**입니다. 판매 표(sales)와 샘플 데이터 SQL, 그리고 완성된 조회 페이지(list.html)까지 들어 있습니다. 어제 어디까지 갔는지에 따라 아래 두 갈래 중 하나로 시작합니다.

## 갈래 1 - 어제 조회 페이지 배포까지 끝난 분

**이 폴더가 필요 없습니다.** 어제 쓰던 내 폴더에서 그대로 시작합니다.

1. 어제 폴더를 VS Code로 열고 `claude` -> `/start`
2. `day13-kit.md`(이 폴더 안에 있음)만 열어 두고, 키트의 문장을 복사해 씁니다

## 갈래 2 - 어제 막혔던 분 (조회 페이지가 안 되는 상태)

이 폴더로 갈아타면 5분 안에 오늘 출발선에 섭니다.

1. **폴더 열기** - 이 폴더(day13-starter)를 VS Code로 엽니다 (File > Open Folder)
2. **환경 확인** - 터미널에서 `claude` 실행 -> `/start` -> `[환경OK]` 한 줄 확인
3. **표와 데이터** - Supabase 대시보드 -> SQL Editor -> 이 폴더의 `setup.sql`을 통째로 붙여넣고 Run 한 번 (어제 이미 만든 분이 실행해도 안전합니다 - 표가 있으면 건너뛰고, 샘플은 비어 있을 때만 들어갑니다)
4. **열쇠 연결** - 두 값(SUPABASE_URL, SUPABASE_ANON_KEY)이 Vercel에 이미 있으면 건너뜁니다. 없으면: Supabase Settings > API에서 확인 -> Vercel Settings > Environment Variables에 입력
5. **배포** - `claude`에서 `/deploy` -> 나온 주소를 #실습공유에 올립니다

배포 주소의 `list.html`에서 샘플 판매 데이터가 보이면 어제 완료 상태와 같습니다. 이제 `day13-kit.md`의 0번부터 진행합니다.

## 이 폴더에 미리 되어 있는 것

- `setup.sql` - 판매 표 + 넣기·읽기 정책 + 샘플 데이터 30건(실행 시점 기준 최근 3일로 들어가서 일별 보기 실습이 됩니다)
- `list.html` - 어제의 도착점인 판매 현황 조회 페이지 완성본
- `index.html` + `api/submit.js` - 주문 등록(넣기) 경로
- `CLAUDE.md` - 오늘 만들 파일(detail.html)이 파일 규칙에 미리 등록돼 있고, 맨 아래 "내 규칙" 자리가 비워져 있습니다 - 오후 실습에서 여러분이 채웁니다

## 오늘 만드는 것 (미리 안 만들어져 있습니다 - 실습입니다)

- 오전: 상세 페이지(`detail.html?id=N`) - 목록의 한 건이 자기 주소를 가진 페이지로 열립니다
- 오후: CLAUDE.md 맨 아래 "내 규칙"에 규칙 1줄을 넣고, 같은 지시를 규칙 전/후로 시켜 행동 차이를 확인합니다

둘 다 `day13-kit.md`의 지시문을 쓰면 됩니다.
